# TM INDEX 精度向上 診断書 v1.0

対象: TURF MATRIX Intelligence Engine
診断者: Chief AI Architect

## 前提

- コード修正はまだ行わない。
- 現状分析・原因仮説・改善優先順位・検証計画のみを扱う。
- 正本（`DESIGN-*.md`）は無断変更しない。
- 人気・オッズをTM INDEX能力評価へ混入させない原則を維持する。

最重要テーマは、「上位3頭に勝ち馬を含める」段階から「最も勝つ馬を1位に置く」段階へ進むことである。

## 1. 総合診断

**現在のTM INDEX完成度: 62 / 100**

β初期として妥当。候補抽出は既に実用水準だが、順位付けは未成熟という健全な発展段階にある。

### 良い点

1. **候補抽出は機能している（最大の資産）**
   - 土日18レースで指数上位3頭の複勝回収率は75.4%、勝ち馬の56%（10/18）を捕捉した。
   - 「能力評価の骨格が正しい」ことを示している。
2. **土台のデータ品質が担保されている**
   - JOIN不一致0、Value二重計算解消、サンプル不足の収縮方式、極端EVの参考化まで対応済み。
   - 精度を測る前提となる「数字の正しさ」が固まっている。
3. **決定性・検証可能性が保たれている**
   - 実行時にLLMを使わず、archiveによる事後検証が可能。

### 重大な問題

問題の本質はただ一つ、**「集合として正しいが、集合内の序列が弱い」**ことである。

- 指数上位3頭の複勝率: 37.0%（土日）/ 33%（日曜）
- 指数1位の勝率: 22%（日曜9頭中2勝）
- 単勝1番人気の一般的な期待勝率: 約32〜33%

指数1位の勝率22%は市場1番人気の期待勝率を下回る。上位3頭という網は正しく張れているが、その中のどれが一番かを市場より正確には当てられていない。

これはAbilityの失敗というより、上位数頭を分離する最終解像度の不足である。指数差1〜3ポイントの僅差帯に真の勝ち馬が埋もれ、補助ファクターのノイズが序列を撹乱している可能性が高い。

## 2. 原因候補（重要度順）

### 原因1（最重要）僅差帯の過剰な順位化

TM INDEXは連続値だが、上位数頭は1〜3ポイント差に密集する。この差の多くは統計的に有意でないノイズの可能性が高いのに、システムは1位・2位・3位と確定的な序列を与えている。

- 根拠: 上位3頭の複勝率は高いのに1位勝率が低い。
- 必要な確認: 各レースの1位と2位のINDEX差と、1位が実際に3着以内だったかの相関。

### 原因2（重要）補助ファクターによる終盤逆転

Abilityで正しく上位に来た馬が、Course / Pace / Training / Bloodの加点で順位を落とし、Ability 2〜3番手が1位へ繰り上がっている疑いがある。

- 根拠: 日曜は指数2〜3位から3勝、指数1位から2勝。
- 必要な確認: 各エンジンのスコア分布（平均・標準偏差・レンジ）。標準偏差がAbilityと大きく異なるエンジンは撹乱源候補。

### 原因3（重要）相手関係・レースレベル補正の不足

ZI・着差・着順は「その馬が何をしたか」だが、「誰を相手にしたか」の補正が弱いと、低レベル戦で好走した馬を過大評価する。

- 根拠: 新潟8R麒麟山特別で指数上位3頭が10・15・13着。
- 必要な確認: レースレベル（出走馬の平均ZI、勝ち上がり時計等）別に指数上位3頭の成績を層別する。

### 原因4（中）道悪・特に重不良ダートの評価崩壊

馬場は表示しているが、馬ごとの道悪適性差を指数へ十分に反映できていない可能性がある。良馬場前提の能力値が道悪で通用しない。

- 必要な確認: 良・稍重・重・不良別の指数上位3頭複勝率。現状はサンプルが薄いため、結論を急がず蓄積を優先する。

### 原因5（中）confidenceが順位の不確実性を表現していない

現状のconfidenceは主にデータ充足度を測るが、「1位と2位が僅差で順位が不確実」という順位の信頼度は表現していない。82と81を明確な差と誤読させる。

## 3. 最優先で直すべき項目（P0 / P1 / P2）

大原則: INDEX本体の改善が先、Value改善は後。INDEXが正しくなければ勝率・EV・乖離度も誤る。

### P0（今すぐ・INDEX本体）

- **P0-1. 各エンジンのスコア分散を計測し正規化する**
  - 全エンジンを共通の平均・標準偏差へ揃え、分散の大きいエンジンが順位を支配する状態を止める。
  - 重みを変える前に必ず行う。
- **P0-2. 僅差帯を可視化する**
  - 1位と2位のINDEX差が閾値未満（例2.0）のとき、データとして「順位信頼度low」を持たせ、archiveへ記録する。
  - まず「僅差だと当たらない」を実証する。

### P1（次・INDEX本体）

- **P1-1. 相手関係 / レースレベル補正の導入**
  - 人気・オッズは使わず、出走馬のZI分布・クラス実績から算出する。
- **P1-2. confidenceに順位不確実性を統合**
  - データ充足度に加え、上位馬とのINDEX差を反映する。

### P2（その後・要データ蓄積）

- **P2-1. 道悪適性補正**
  - 結果データ（着順・馬場）の蓄積を前提とする。
- **P2-2. Value / 乖離度の再設計**
  - INDEXが安定してから着手する。

## 4. 各エンジンの診断

| エンジン | 診断 | 主な懸念 | 対応 |
| --- | --- | --- | --- |
| Ability | 機能している（骨格） | ZI・過去走の絶対値過信の可能性 | レースレベル補正で相対化（P1-1） |
| Blood | reasonは充実、スコア根拠が弱い | 適性の絶対評価とAbilityの二重計上リスク | 同馬内差分方式を検討 |
| Training | 時計評価は妥当 | 分散が大きく順位を撹乱する疑い | 分散正規化（P0-1）の主対象 |
| Course | 加点方向は正しい | Bloodと適性で二重加算の疑い | 責務分離を明文化 |
| Pace | 展開評価は妥当 | 分散不揃いで終盤逆転の一因 | 分散正規化（P0-1） |
| Stable | 補助として妥当 | 影響が過大なら順位撹乱 | 重み検証 |
| Form | 近走推移は有用 | Abilityの近走推移と二重計上の疑い | 責務分離 |

### 二重加算の潜在リスク

1. Ability「近走推移」× Form: 両方が近走トレンドを見ている。
2. Blood「距離・コース適性」× Course: 今回条件への適性を二重加点する可能性。
3. Blood / Courseの適性 × Ability: 道悪好走の多くは地力の反映でもある。

## 5. TM INDEX 精度向上案

### スコアリング・重み・正規化

- 上位帯でINDEX差が閾値未満の馬は「同格クラスター」として扱い、確定的な差とみなさない設計を検討する。
- 重みを触る前に分散を正規化する。
- 全エンジンをz-score化（平均0・標準偏差1）してから重み付けする案を検証する。
- 正規化後に、各エンジンスコアと着順の相関を測り、相関の高いエンジンへ重みを寄せる。感覚で重みを決めない。

### 相手関係

- 出走馬のZI分布・クラス実績からレースレベルを算出し、Abilityを相対化する。
- 人気・オッズは使用しない。

### 馬場適性

- 同馬内差分方式（道悪時−良馬場時）で地力の二重計上を避ける。
- 芝とダートを分離する。
- 結果データ蓄積後に着手する。

### confidence

- 「データ充足度×上位馬とのINDEX差」の合成を検討する。
- 僅差1位はconfidenceを下げる。

### タイブレーク

- 現状の同点処理をAbility優先へ寄せる。
- 同INDEX・僅差なら補助ファクターではなくAbilityスコアが高い馬を上位にする「実力が確かな馬を上に」の原則を検証する。

## 6. 検証計画

全て`data/archive/`の蓄積データに対し、`tools/analyze/`のオフライン集計で実施する。

1. 各エンジンスコアの分布（平均・SD・レンジ）。
2. 各エンジンスコアと着順・着差の相関係数。
3. INDEX 1位 / 2位 / 3位それぞれの勝率・複勝率。
4. 1位−2位のINDEX差別の1位複勝率。
5. confidence別の1位精度。
6. 芝 / ダート別。
7. 良 / 稍重 / 重 / 不良別。
8. 重賞 / 特別 / 一般別。
9. キャリア / 年齢 / 所属別。
10. 修正前後のバックテスト。

### バックテスト方法

- 時系列分割: 過去週で係数を決め、次週で検証する。未来のデータで学習しない。
- 指標: 指数1位の勝率・複勝率、上位3頭の複勝率、順位相関（Spearman）。

### 合格基準

- 指数1位の勝率が市場1番人気の勝率（約33%）に接近または上回る。
- 上位3頭の複勝率を維持または向上し、現在の抽出力を壊さない。
- 修正で悪化した層（芝 / ダート / 馬場 / クラス）がない。

### 過学習防止策

- 最低100〜300頭、複数週を確保してから係数を確定する。
- 現在の18レース54頭では、データ量に依存しない分散計測までに限定する。
- 相手関係・重み最適化はサンプルが閾値に達するまで係数を凍結する。
- 1週で良化しても翌週に再現しなければ棄却する。

## 7. 実装順序（5 Sprint）

### Sprint 1 - 計測（データ量に依存しない構造改善）

- 各エンジンのスコア分布・相関を`tools/analyze/engine-stats.mjs`で集計する。
- 1位−2位INDEX差と1位複勝率を集計する。
- 受入: 8エンジンのSD・レンジ・対着順相関を一覧化し、撹乱源候補を特定する。
- **この時点でコードのロジックは変えない。**

### Sprint 2 - 分散正規化（P0-1）

- 全エンジンスコアをz-score化してから重み付けする層を追加する。
- 受入: 上位3頭複勝率を維持し、指数1位勝率が悪化せず、分散の大きいエンジンの順位支配が減る。

### Sprint 3 - 重みの相関ベース最適化 + タイブレーク

- Sprint 1の相関に基づき重みを調整し、同点タイブレークをAbility優先へ変更する。
- 受入: 100頭以上のバックテストで指数1位勝率が改善し、悪化層がない。

### Sprint 4 - 相手関係 / レースレベル補正 + confidence統合

- ZI分布・クラス実績からレースレベルを算出しAbilityを相対化する。
- confidenceへ順位不確実性を統合する。
- 受入: 特別・条件戦での上位3頭複勝率が改善し、人気・オッズ未使用を確認する。

### Sprint 5 - 二重計上の解消 + 道悪適性

- Form / Blood / CourseとAbilityの責務を分離する。
- 道悪適性を同馬内差分で導入する。
- 受入: 責務分離後も総合精度が維持または向上し、道悪レースで改善する。

## 8. 公開上の判断

### 現在の指数を公開してよいか

**YES（条件付き）**。上位3頭の抽出は市場平均を超える複勝率で機能しており、公開に値する。嘘のある数字ではない。

指数1位の序列精度が発展途上である旨を開示することを推奨する。TM INDEXは全馬の相対評価であり、特に上位数頭が僅差の場合、順位はあくまで目安である。

一時的に非表示にすべき指標はない。ただしValue / 妙味は「参考」の位置づけを維持し、強い推奨として見せない。

## 総括

今すべきことは、重みをいじることでも新ファクターを足すことでもない。

1. Sprint 1で撹乱源を特定する（計測）。
2. Sprint 2で分散を正規化する（データ量非依存の安全な構造改善）。

TM INDEXは壊れているのではなく、解像度が足りない。骨格（候補抽出）は既に正しい。僅差帯を分離する精度を、感覚ではなく相関とバックテストで詰める段階にある。
